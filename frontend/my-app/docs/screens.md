# 화면 목록

스코프(Slack 실연동 / 분기 준비 / 자동 판정·발송 / 다국어 / 텍스트 입출력 / 1왕복 / LLM 호출 2회) 기준으로 정리. "안 한다" 목록(결정 기록, Slack 외 플랫폼, 다음 왕복, 로그인·회원가입, 첨부파일, 실시간 동기화)에 해당하는 화면은 만들지 않았다.

라우트 경로는 `react-router` 기준 제안이며, 스켈레톤 단계에서 그대로 구현했다.

---

## 1. Landing — `/`

- **목적**: 서비스 소개, 시작 진입점. "잠들기 전에 바통을 넘겨두세요" 핵심 카피.
- **진입 경로**: 최초 접속, 또는 Slack 연결이 끊긴 상태에서 재방문.
- **필요한 데이터**: 없음.
- **사용자 행동**: "시작하기" 클릭.
- **나가는 경로**: `/connect` (Slack 미연결) 또는 `/home` (이미 연결된 세션이면 바로 스킵 — 아래 미해결 질문 참고).

## 2. Slack 연결 — `/connect`

- **목적**: Slack OAuth 시작.
- **진입 경로**: Landing에서 "시작하기", 또는 Settings에서 재연결.
- **필요한 데이터**: 없음 (연결 성공 시 `PlatformConnection` 생성).
- **사용자 행동**: "Slack 연결하기" 클릭 → Slack OAuth 화면으로 이동(외부).
- **나가는 경로**: OAuth 완료 후 Slack이 `/connect/callback`으로 리다이렉트.

## 3. Slack 연결 콜백 처리 — `/connect/callback`

- **목적**: OAuth 콜백 코드 교환 처리 중 로딩 화면.
- **진입 경로**: Slack OAuth 리다이렉트.
- **필요한 데이터**: URL의 `code` 파라미터.
- **사용자 행동**: 없음 (자동 처리, 로딩 스피너).
- **나가는 경로**: 성공 시 `/conversations`, 실패 시 `/connect/error`.

## 4. Slack 연결 실패 — `/connect/error`

- **목적**: OAuth 실패(권한 거부, 네트워크 오류 등) 안내 + 재시도.
- **진입 경로**: `/connect/callback`에서 실패.
- **필요한 데이터**: 실패 사유 문구.
- **사용자 행동**: "다시 시도" → `/connect`.
- **나가는 경로**: `/connect`.

## 5. 바통 홈 (대기 목록) — `/home`

- **목적**: 진행 중인 모든 바통을 상태별로 보여주는 대시보드. 데모의 두 헤드라인 시나리오 진입점.
- **진입 경로**: 연결 완료 후 기본 진입 화면. 이후 세션에서도 기본 진입점.
- **필요한 데이터**: `Baton[]` (+ 연결된 `Conversation`, 최신 `Message` 요약), `PlatformConnection.lastSyncedAt`.
- **사용자 행동**: "새 바통 만들기"(`/conversations`), 바통 카드 클릭(상태별로 `/batons/:id`, `/batons/:id/pending`, `/batons/:id/result` 중 하나), "개인 설정"(`/settings`).
- **나가는 경로**: 위 참고.

## 6. 대화 선택 — `/conversations`

- **목적**: 트리거 메시지를 보낼 Slack 채널/DM 선택.
- **진입 경로**: Home의 "새 바통 만들기".
- **필요한 데이터**: `Conversation[]` (Slack API로 채널/DM 목록 조회).
- **사용자 행동**: 대화 하나 선택.
- **나가는 경로**: `/conversations/:conversationId/compose`.

## 7. 바통 생성 (메시지 작성) — `/conversations/:conversationId/compose`

- **목적**: 상대에게 보낼 트리거 메시지 작성.
- **진입 경로**: 대화 선택.
- **필요한 데이터**: 선택된 `Conversation`.
- **사용자 행동**: 메시지 입력 → "분기 준비" 클릭 (이 시점에 LLM 호출 1회: 분기 3개 제안 생성).
- **나가는 경로**: `/conversations/:conversationId/branches`.

## 8. 분기 준비 — `/conversations/:conversationId/branches`

- **목적**: AI가 제안한 답변 유형 3개 + 응답 초안을 확인/편집하고 트리거 메시지를 실제로 발송. 핵심 기능 ①.
- **진입 경로**: 바통 생성 화면에서 넘어옴.
- **필요한 데이터**: `Branch[]` (AI 생성, 아직 저장 전이면 임시 상태), 트리거 메시지 본문.
- **사용자 행동**: 각 분기 카드의 응답 초안 편집(단순 카드 — 유형 라벨 + 초안 + 편집만, 액션 선택 UI 없음), "발송" 클릭.
- **나가는 경로**: 발송 완료 → `/home` (새 바통이 `active` 상태로 목록에 표시).

## 9. 바통 상세 (답장 대기 중) — `/batons/:batonId`

- **목적**: 아직 답장이 오지 않은 `active` 바통의 상세 — 준비된 분기, 경과 시간, 만료까지 남은 시간.
- **진입 경로**: Home에서 대기 중 바통 카드 클릭.
- **필요한 데이터**: `Baton`, `Branch[]`, `Conversation`.
- **사용자 행동**: 없음(읽기 전용) 또는 Home으로 돌아가기.
- **나가는 경로**: `/home`.

## 10. 보류 응답 처리 — `/batons/:batonId/pending`

- **목적**: 자동 판정이 보류된 바통 처리. 핵심 기능 ②의 보류 분기. 한 화면에서 두 상태를 분기 렌더링:
  - **`is_ambiguous`** (판정 애매): 후보 분기 2개를 나란히 보여주고 사용자가 고르게 함.
  - **`containsNewQuestion`** (새 질문 포함): 분기 선택 UI 없이 상대의 새 질문을 강조 표시, 직접 작성 유도. 확신도와 무관하게 항상 이 상태.
- **진입 경로**: Home의 "보류 응답 처리" 카드.
- **필요한 데이터**: `Baton`, `Classification`, 답장 `Message`, (is_ambiguous인 경우) 후보 `Branch` 2개.
- **사용자 행동**: (is_ambiguous) 분기 선택 후 발송 / (containsNewQuestion) 직접 응답 작성 후 발송.
- **나가는 경로**: 발송 완료 → `/home`.

## 11. 자동 발송 결과 확인 — `/batons/:batonId/result`

- **목적**: 자동 발송된 응답 확인(발송된 분기, 판정 근거 요약). 핵심 기능 ②의 성공 분기.
- **진입 경로**: Home의 "결과 확인" 카드.
- **필요한 데이터**: `Baton`, `Execution`, `Classification`, 발송된 `Message`.
- **사용자 행동**: 확인 클릭 (읽음 처리 → `completedAt` 세팅).
- **나가는 경로**: `/home`.

## 12. 동기화 오류 — `/sync-error`

- **목적**: Slack 동기화 실패(토큰 만료, API 오류 등) 안내.
- **진입 경로**: Home의 "동기화 오류 확인".
- **필요한 데이터**: `PlatformConnection.connectionStatus`, 실패 사유.
- **사용자 행동**: "재연결" → `/connect`.
- **나가는 경로**: `/connect` 또는 `/home`.

## 13. 개인 설정 — `/settings`

- **목적**: 언어 설정(다국어 스코프), Slack 연결 상태 확인/해제.
- **진입 경로**: Home.
- **필요한 데이터**: `User`, `PlatformConnection`.
- **사용자 행동**: 언어 변경, 연결 해제.
- **나가는 경로**: `/home`.

## 원래 흐름과 달라진 점 / 지적 사항

1. **로그인이 없는데 "사용자"는 어떻게 식별되나** — Slack OAuth 연결 자체가 사실상 로그인 역할을 한다고 가정함(최초 연결 시 `users` row 자동 생성). 맞는 가정인지 확인 필요.
2. **OAuth 실패·콜백 로딩·동기화 오류 화면 3개(`/connect/callback`, `/connect/error`, `/sync-error`) 추가함** — "Slack 실연동"이 스코프에 들어오면서 실패 경로가 필연적으로 생기는데, 제시된 흐름엔 없었음.
3. **"바통 상세(`/batons/:batonId`, 답장 대기 중)" 화면 추가함** — Home 목록에서 "대기 중" 카드를 눌렀을 때 갈 곳이 필요.
4. **FinalConfirm을 별도 화면으로 두지 않고 "분기 준비" 화면의 발송 버튼에 합침** — 클릭 수를 줄이기 위함. 확인 모달(발송 전 alert) 정도는 필요하면 나중에 추가 가능.
5. **"결정 기록"(History) 화면은 만들지 않음** — 스코프의 "안 한다" 목록에 있음. (참고: 기존 `my-app`에 있던 프로토타입엔 있었으나 이번에 제외함.)
6. **설정(`/settings`) 화면 추가함** — 다국어가 스코프에 있는데 언어를 바꿀 곳이 명시되지 않아서 넣음. 필요 없으면 빼도 됨.

## 데모 시연 동선

두 시나리오 모두 **Home에서 시작해 1클릭**으로 도달하도록 목데이터를 구성한다 (`src/api/mock/` 참고).

**(a) 새 질문 없는 답장 → 자동 발송 성공**
`/home` → "결과 확인" 카드 클릭 → `/batons/:id/result` (발송된 응답 확인)
→ 총 1클릭.

**(b) 새 질문 섞인 답장 → 보류 후 알림**
`/home` → "보류 응답 처리" 카드 클릭 → `/batons/:id/pending` (containsNewQuestion 상태, 새 질문 강조 + 직접 작성)
→ 총 1클릭.

전체 흐름(Slack 연결 → 대화 선택 → 바통 생성 → 분기 준비 → 발송)은 라이브로 한 번 시연하고, "답장이 도착한 이후" 두 시나리오는 미리 시드된 바통으로 즉시 보여주는 걸 추천함 — 실제 Slack 답장을 라이브로 기다리는 건 데모 리스크가 큼.
