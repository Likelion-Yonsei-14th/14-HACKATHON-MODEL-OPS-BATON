# BATON Frontend 작업 지침

이 문서는 이 저장소에서 작업하는 코딩 에이전트와 개발자가 따라야 할 규칙입니다. 사용자의 명시적인 요청과 저장소의 실제 코드·설정이 이 문서보다 우선합니다.

## 작업 전 확인

1. 관련 화면, 도메인, 타입과 테스트를 먼저 확인합니다.
2. `README.md`, `docs/DESIGN_TOKENS.md`, `.env.example`에서 현재 기준을 확인합니다.
3. 요청과 관계없는 파일이나 사용자의 기존 변경을 수정하지 않습니다.
4. 기술 버전은 `package.json`과 lockfile을 기준으로 판단합니다.

## 절대 변경하면 안 되는 제품 원칙

- AI가 새로운 결정, 약속, 일정, 비용 또는 범위를 만들게 하지 않습니다.
- 모든 분기는 `Condition → Decision → Action`을 함께 표현합니다.
- 하나의 BATON은 최대 한 번만 자동 실행됩니다.
- 사람이 직접 개입한 BATON은 자동 실행을 계속하는 것처럼 표시하지 않습니다.
- BATON이 생성한 메시지가 다른 BATON을 작동시키는 흐름을 만들지 않습니다.
- 애매함, 범위 초과, 새로운 질문, 동기화 오류는 성공 상태가 아니라 검토 또는 오류 상태로 표시합니다.
- 자동 발송 사실과 사전 승인 사실을 숨기지 않습니다.

## UX 원칙

- 기본 경험은 `AI가 생성하고 사용자가 검토`하는 흐름입니다.
- 빈 캔버스에서 workflow를 처음부터 조립하도록 요구하지 않습니다.
- confidence threshold, rule JSON, 모델 설정은 기본 화면에 노출하지 않습니다.
- timezone은 단순 시계가 아니라 상대방의 근무 가능 상태를 이해하는 정보로 다룹니다.
- 로딩, 빈 상태, 오류, 연결 끊김, 검토 필요 상태를 정상 흐름과 동등하게 구현합니다.
- 색상만으로 상태를 구분하지 않고 텍스트나 아이콘을 함께 제공합니다.

## 코드 구조

- 도메인 로직은 `features/` 아래에 배치합니다.
- 페이지 컴포넌트에서 직접 API를 호출하지 않습니다.
- API 호출, 서버 상태 hook, 화면 컴포넌트를 분리합니다.
- 백엔드 DTO를 여러 화면에 직접 확산하지 않습니다. 필요하면 mapper를 둡니다.
- 공용 UI 컴포넌트에 BATON 도메인 규칙을 넣지 않습니다.
- 환경변수는 한 곳에서 검증하고 임의로 `process.env`를 참조하지 않습니다.
- 시간 값은 ISO 8601 기준으로 받고, 표시할 때 사용자의 timezone을 적용합니다.

## 디자인

- `docs/DESIGN_TOKENS.md`가 비어 있는 동안 임의의 값을 공식 토큰으로 문서화하지 않습니다.
- 합의된 시맨틱 토큰이 생기면 하드코딩 값보다 우선합니다.
- 새로운 토큰을 추가할 때 문서와 실제 테마 정의를 같은 변경에 포함합니다.

## 검증

변경 범위에 맞게 다음 명령을 실행합니다.

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

- 동작 변경에는 관련 테스트를 추가하거나 수정합니다.
- 주요 사용자 흐름 변경은 모바일과 데스크톱에서 확인합니다.
- 명령이 아직 구성되지 않았거나 실행할 수 없으면 그 사실을 결과에 명시합니다.

## 보안 및 데이터

- token, webhook secret, 실제 메시지 내용, 개인정보를 코드·테스트 fixture·로그에 넣지 않습니다.
- `.env.local` 등 로컬 환경 파일을 커밋하지 않습니다.
- 사용자에게 내부 chain-of-thought를 노출하거나 저장하지 않습니다. 짧은 판정 설명만 사용합니다.
- mock 데이터에는 실제 사용자의 이름, 이메일, Slack ID를 사용하지 않습니다.

## 문서 동기화

실행 명령, 환경변수, 폴더 구조, 핵심 UX 또는 API 계약이 달라지면 관련 README와 예시 파일도 함께 갱신합니다.
